## ตั้งต้นและเข้าสู่ระบบ

### BE-01 · ตั้งโปรเจกต์ Go Fiber + เชื่อม PostgreSQL

สร้างโครงโปรเจกต์ Fiber อ่านค่าจาก `.env` และเชื่อม PostgreSQL ด้วย GORM

**เกณฑ์เสร็จ**

- [x] `GET /api/health` ตอบ 200
- [x] ถ้าต่อฐานข้อมูลไม่ได้ แอปหยุดทำงานพร้อมข้อความบอกสาเหตุ
- [x] success ทุกตัวตอบ `{"status":200,"data":...,"message":"success"}` (ตัด `data` ออกเมื่อไม่มีข้อมูล) และ error ตอบ `{"status":<HTTP status>,"message":"..."}`

**รันในเครื่อง**

1. เปิด Docker Desktop ให้ Docker Engine พร้อมทำงาน
2. คัดลอก `.env.example` เป็น `.env` หากยังไม่มีไฟล์ `.env`
3. เปิด PostgreSQL ด้วย `docker compose up -d postgres`
4. สร้าง schema ตาราง และข้อมูลตั้งต้นด้วย `go run ./cmd/migrate`
5. สร้างแอดมินคนแรกตามคำสั่งใน BE-02
6. รัน API ด้วย `go run ./cmd/api`
7. ตรวจสอบด้วย `GET http://localhost:8081/api/health`
8. เปิด Swagger UI ที่ `http://localhost:8081/api/docs`

เมื่อต้องการบัญชีตัวอย่างสำหรับ local ให้รัน `go run ./cmd/seed-sample` หลัง migration คำสั่งนี้อ่าน `sample-data/users.json`, ตั้งหัวหน้าฝ่าย และซ่อมหัวข้อเปิดที่เคยถูกสร้างโดยไม่มีผู้ต้องส่ง โดยไม่เปลี่ยนรหัสผ่านของบัญชีตัวอย่างที่มีอยู่แล้ว บุคลากรทุกคนอยู่ทุกฝ่ายโดยอัตโนมัติ จึงไม่มีข้อมูล membership รายบุคคล

แอปตรวจตอนเริ่มว่า role ที่ต่อเห็นตารางใน schema ตาม `DB_SCHEMA` (ค่าเริ่มต้น `sdms`) ถ้าไม่ตรงจะหยุดพร้อมบอกวิธีแก้

### BE-05 · API จัดการบุคลากร

`GET /api/users` · `GET` · `POST /api/admin/users` · `PATCH /api/admin/users/{uuid}` · `POST /api/admin/users/{uuid}/password`

ต้องทำก่อน: BE-04

**เกณฑ์เสร็จ**

- [x] ใช้ได้เฉพาะแอดมิน
- [x] เพิ่มบุคลากรด้วยคำนำหน้า ชื่อ นามสกุล username รหัสผ่านเริ่มต้น และบทบาทผู้บริหาร/แอดมิน โดยทุกบัญชีอยู่ทุกฝ่ายอัตโนมัติ
- [x] username ซ้ำ → 409
- [x] ปิดใช้งานแทนการลบ คำตอบเดิมของคนนั้นยังอยู่
- [x] ตั้งรหัสผ่านใหม่แล้ว session เดิมของคนนั้นใช้ไม่ได้

**Request fields**

- `POST /api/admin/users`: `username`, `password`, `prefix`, `first_name`, `last_name`, `is_exec`, `is_admin`
- `PATCH /api/admin/users/{uuid}`: ส่งเฉพาะ field ที่ต้องแก้ โดยใช้ `is_active: false` เพื่อปิดบัญชี
- `POST /api/admin/users/{uuid}/password`: `password`

ทุก response ที่มีข้อมูลบุคลากรคืนทั้ง `prefix`, `first_name`, `last_name` และ `full_name` ที่ประกอบขึ้นเพื่อให้ frontend รุ่นเดิมยังใช้งานได้ ส่วน request ยังรับ `full_name` แบบเดิมชั่วคราว แต่ห้ามส่งพร้อมช่องชื่อแบบใหม่

`GET /api/users` ใช้ได้หลัง login และคืนเฉพาะบัญชีที่เปิดใช้งาน พร้อม UUID, ชื่อ, ฝ่ายทั้งหมด และ `is_topic_assignee_eligible: true` สำหรับสร้างตัวเลือกผู้ต้องส่ง รวมทั้งหัวหน้าฝ่ายและผู้บริหาร แต่ไม่คืน username, password hash, บทบาท หรือข้อมูลสถานะสำหรับงานแอดมิน ใช้รายการนี้สร้างตัวกรอง `by` ในหน้าค้นหาได้ด้วย

### BE-06 · นำเข้าบุคลากรจาก Excel/CSV

`POST /api/admin/users/import` · `GET /api/admin/users/import/template.csv` · `GET /api/admin/users/import/template.xlsx`

ต้องทำก่อน: BE-05

**เกณฑ์เสร็จ**

- [x] รับไฟล์ .xlsx และ .csv คอลัมน์: คำนำหน้า, ชื่อ, นามสกุล, username, รหัสผ่านเริ่มต้น
- [x] ตรวจทุกแถวก่อนบันทึก ถ้ามีแถวผิดให้คืนรายการผิดทีละบรรทัด และไม่บันทึกเลยสักแถว
- [x] มีไฟล์ตัวอย่างให้ดาวน์โหลด

**รูปแบบนำเข้า**

- ส่งแบบ `multipart/form-data` โดยใช้ field ชื่อ `file` ขนาดไม่เกิน 3 MiB และไม่เกิน 2,000 แถวข้อมูล
- คอลัมน์ `ฝ่าย` ใช้รหัส ชื่อเต็ม หรือชื่อย่อของฝ่ายได้ หากมีหลายฝ่ายให้คั่นด้วย `|`, `,` หรือ `;`
- บัญชีจากไฟล์จะเป็นบุคลากรทั่วไปโดยค่าเริ่มต้น (ไม่ให้สิทธิ์ผู้บริหารหรือแอดมิน)
- ถ้าไฟล์มีข้อมูลผิด API ตอบ `400` ด้วย error envelope มาตรฐานและไม่บันทึกข้อมูลทั้งไฟล์

## หัวข้อและฟอร์ม

### BE-08 · API สร้างหัวข้อ + ช่องฟอร์ม

`POST /api/topics`

ต้องทำก่อน: BE-04

**เกณฑ์เสร็จ**

- [x] สร้างได้เฉพาะหัวหน้าฝ่ายนั้นกับแอดมิน
- [x] รับชื่อหัวข้อ กำหนดส่ง ลับ/ไม่ลับ และรายการช่อง (ชนิด ชื่อ ต้องกรอกหรือไม่ ตัวเลือก ลำดับ)
- [x] ช่องมี 6 ชนิด: ข้อความ ข้อความยาว ตัวเลข วันที่ ตัวเลือก ไฟล์
- [x] หัวข้อผูกกับปีการศึกษาปัจจุบันอัตโนมัติ
- [x] ชื่อว่าง หรือช่องตัวเลือกมีน้อยกว่า 2 ข้อ → 400 บอกว่าช่องไหนผิด

**Request fields**

- ส่ง JSON ที่มี `division_uuid`, `title`, `due_date` รูปแบบ `YYYY-MM-DD`, `is_secret`, `fields` และส่ง `assignee_uuids` เป็น UUID ของผู้ต้องส่งที่เลือกได้
- แต่ละช่องรับ `type` (`text`, `para`, `num`, `date`, `choice`, `file`), `label`, `required`, `options` และ `position`; หากไม่ส่ง `required` จะใช้ `true`
- ช่อง `choice` ต้องมี `options` ที่ไม่ซ้ำอย่างน้อย 2 ค่า ส่วนช่องชนิดอื่นห้ามมีตัวเลือก
- หากส่ง `assignee_uuids` ต้องมีอย่างน้อย 1 คน UUID ห้ามซ้ำ และทุกคนต้องเป็นบัญชีที่เปิดใช้งาน โดยเลือกหัวหน้าฝ่าย ผู้บริหาร หรือแอดมินได้; หากไม่ส่ง field นี้จะเลือกบัญชีที่เปิดใช้งานทั้งหมด
- ระบบสร้างหัวข้อ ช่องฟอร์ม และรายชื่อผู้ต้องส่งใน transaction เดียวกัน โดย response จาก endpoint จัดการหัวข้อคืนทั้ง `assignee_count` กับ `assignee_uuids` (response ฝั่งส่งงานไม่เปิดเผย UUID ทั้งชุด)
- หากระบบยังไม่มีบัญชีเปิดใช้งาน ระบบไม่สร้างหัวข้อและตอบ `409`
- validation error ตอบ `400` ด้วย `status` และ `message`

### BE-09 · API แก้ / ปิดรับ / เปิดรับ / ลบหัวข้อ

`PATCH /api/topics/{uuid}` · `POST /api/topics/{uuid}/close` · `POST /api/topics/{uuid}/reopen` · `DELETE /api/topics/{uuid}`

ต้องทำก่อน: BE-08

**เกณฑ์เสร็จ**

- [x] แก้ได้เฉพาะหัวหน้าฝ่ายนั้น แอดมิน และคนสร้างหัวข้อ
- [x] เปลี่ยนชนิดช่องเดิมหลังมีคนส่งแล้ว → 409
- [x] ลบช่องที่มีคำตอบแล้ว = ซ่อนช่องนั้น ข้อมูลยังอยู่
- [x] ลบหัวข้อที่มีคนส่งแล้ว → 409

**รูปแบบการแก้ไข**

- `PATCH` ส่งเฉพาะ `title`, `due_date`, `is_secret` ที่ต้องการแก้ได้
- `PATCH` รับ `assignee_uuids` เป็นรายชื่อผู้ต้องส่งฉบับเต็ม เพิ่มผู้เข้าเงื่อนไขหรือถอดผู้ที่ยังไม่ส่งได้; ผู้ที่ส่งแล้วถอดไม่ได้และตอบ `409`
- หากส่ง `fields` ต้องส่งแบบฟอร์มฉบับเต็ม: ช่องเดิมส่ง `uuid`, ช่องใหม่ไม่ส่ง `uuid`, ช่องเดิมที่ไม่อยู่ในรายการถือว่าถูกลบ
- ช่องเดิมที่ไม่ส่ง `required` จะคงค่าเดิม ส่วนช่องใหม่จะใช้ `true` เป็นค่าเริ่มต้น
- ปิดและเปิดรับซ้ำได้โดยไม่เปลี่ยน timestamp โดยไม่จำเป็น; `closed_at` เก็บเวลาปิดล่าสุดแม้เปิดรับใหม่
- conflict ตอบ `409` ด้วย error envelope มาตรฐาน; ลบสำเร็จตอบ `200` ด้วย success envelope แบบไม่มี `data`

### BE-10 · API รายการฝ่ายและหัวข้อ

`GET /api/divisions` · `GET /api/divisions/{code}/topics?year=`

ต้องทำก่อน: BE-08

### BE-11 · เชื่อม Cloudflare R2 + อัปโหลดไฟล์

`POST /api/uploads` · `DELETE /api/uploads/{uuid}`

ต้องทำก่อน: BE-04

**เกณฑ์เสร็จ**

- [x] อัปโหลดทีละไฟล์ แล้วคืน file uuid ให้ FE แนบไปตอนส่งคำตอบ
- [x] ไฟล์ใหญ่เกิน 50 MB → 413
- [x] ไฟล์ไปอยู่ใน Cloudflare R2 แยก object key ตาม ปี / ฝ่าย / หัวข้อ
- [x] ไฟล์ที่อัปโหลดแล้วแต่ไม่ได้ส่งภายใน 24 ชั่วโมงถูกลบอัตโนมัติ
- [x] ตอนพัฒนาใช้โฟลเดอร์ในเครื่องแทน R2 ได้ (สลับด้วยค่าใน `.env`)

**รูปแบบอัปโหลดและตั้งค่า storage**

- ส่ง `multipart/form-data` โดยมี `topic_uuid`, `field_uuid` และไฟล์หนึ่งไฟล์ใน field ชื่อ `file`
- local development ใช้ `FILE_STORAGE_DRIVER=local` และกำหนดตำแหน่งด้วย `LOCAL_UPLOAD_DIR`
- Cloudflare R2 ใช้ `FILE_STORAGE_DRIVER=r2` และตั้ง `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET` ตามตัวอย่างใน `.env.example`
- ระบบจัด object key เป็น `<prefix>/<ปีการศึกษา>/<รหัสฝ่าย>/<topic_uuid>/<file_uuid>.<นามสกุล>` โดย `R2_PREFIX` มีค่าเริ่มต้นเป็น `sdms`
- ค่าเริ่มต้นของ staged TTL คือ 24 ชั่วโมง และ cleanup ทำทุก 1 ชั่วโมง ปรับได้ด้วยค่าที่ระบุใน `.env.example`

### BE-12 · API ส่ง / แก้คำตอบ

`GET /api/me/pending` · `GET /api/topics/{uuid}/my-submission` · `PUT /api/topics/{uuid}/my-submission`

ต้องทำก่อน: BE-08, BE-11

**เกณฑ์เสร็จ**

- [x] `me/pending` คืนหัวข้อที่เปิดรับอยู่และฉันยังไม่ส่ง เรียงตามกำหนดส่ง
- [x] ส่งได้เฉพาะคนที่อยู่ใน snapshot ผู้ต้องส่งของหัวข้อ และหัวข้อต้องยังเปิดรับอยู่
- [x] ช่องที่ต้องกรอกว่าง หรือค่าไม่ตรงชนิด → `400` ด้วย `status` และ `message`
- [x] ส่งซ้ำ = แก้คำตอบเดิม วันที่ส่งครั้งแรกไม่เปลี่ยน
- [x] ส่งครั้งแรกหลังวันกำหนดส่ง (ตามเวลาไทย) → สถานะ `late`

`PUT` รับ JSON รูปแบบ `{"values":{"<field_uuid>":<value>}}` ตามชนิดของช่องใน [sdms-database.md](sdms-database.md) และผูกไฟล์ staged ด้วย UUID ที่ได้จาก BE-11 การแก้คำตอบจะรักษาค่าของช่องที่ถูกซ่อนไว้และลบ object ของไฟล์เดิมที่ผู้ใช้ถอดออก

### BE-13 · API ตารางคำตอบของหัวข้อ

`GET /api/topics/{uuid}?status=` · `GET /api/topics/{uuid}/pending-names`

ต้องทำก่อน: BE-12

**เกณฑ์เสร็จ**

- [x] คืน 1 แถวต่อผู้ต้องส่ง พร้อมค่าทุกช่อง ไฟล์ และวันที่ส่ง
- [x] สถานะมี 5 แบบ: ส่งแล้ว · ช้า · ยังไม่ส่ง · เลยกำหนด · ไม่ส่ง (ปิดรับแล้ว)
- [x] กรองด้วย `status=done` หรือ `status=pending` ได้
- [x] หัวข้อลับ: คนที่ไม่มีสิทธิ์เห็นแค่แถวของตัวเอง
- [x] `pending-names` ใช้ได้เฉพาะคนที่แก้หัวข้อนั้นได้

`GET /api/topics/{uuid}` คืน `topic` และ `rows` โดยแต่ละแถวมีข้อมูลผู้ต้องส่ง, `values` ของช่องที่ใช้งานอยู่ทั้งหมด, ไฟล์ที่ผูกกับคำตอบ, `submitted_at` และสถานะ `submitted`, `late`, `pending`, `overdue` หรือ `not_submitted` ช่องที่ยังไม่มีคำตอบจะคืนค่า `null` เพื่อให้ตารางมีโครงสร้างคงที่ ตัวกรอง `done` รวม `submitted`/`late` ส่วน `pending` รวมสถานะที่ยังไม่มี submission ทั้งหมด

หัวข้อทั่วไปเปิดให้ผู้ใช้ที่เข้าสู่ระบบดูทุกแถว ส่วนหัวข้อลับจะคืนทุกแถวเฉพาะผู้บริหาร หัวหน้าฝ่ายนั้น หรือผู้สร้างหัวข้อ ผู้ต้องส่งคนอื่นจะเห็นเฉพาะแถวของตัวเอง และผู้ที่ไม่อยู่ใน snapshot จะได้รายการว่าง `GET /api/topics/{uuid}/pending-names` คืนรายชื่อผู้ที่ยังไม่มี submission และตรวจสิทธิ์แก้หัวข้อก่อนทุกครั้ง

### BE-14 · API เปิดดู / ดาวน์โหลดไฟล์

`GET /api/files/{uuid}` เปิดดูไฟล์ และ `GET /api/files/{uuid}?download=true` บังคับดาวน์โหลด

ต้องทำก่อน: BE-11, BE-13

**เกณฑ์เสร็จ**

- [x] ตรวจสิทธิ์แบบเดียวกับตารางคำตอบ ไม่มีสิทธิ์ → 403
- [x] PDF รูป และวิดีโอเปิดในระบบได้ พร้อมตัวเลือกดาวน์โหลด
- [x] ดึงไฟล์จาก R2 แบบสตรีม ไม่เปิดเผย R2 URL หรือ credentials ให้ผู้ใช้

endpoint นี้เปิดได้เฉพาะไฟล์สถานะ `attached` ที่แสดงอยู่ในตารางคำตอบ ไฟล์ของหัวข้อทั่วไปเปิดได้หลังเข้าสู่ระบบ ส่วนหัวข้อลับใช้ขอบเขตเดียวกับ BE-13 คือผู้บริหาร หัวหน้าฝ่าย และผู้สร้างหัวข้อเปิดได้ทุกไฟล์ ขณะที่ผู้ต้องส่งทั่วไปเปิดได้เฉพาะไฟล์ของ submission ตนเอง หากไม่มีสิทธิ์ตอบ `403` และ UUID ที่ไม่มีอยู่หรือเป็นไฟล์ staged/trashed ตอบ `404`

ระบบส่ง `application/pdf`, รูป raster และวิดีโอด้วย `Content-Disposition: inline` เพื่อให้ frontend แสดงผ่าน `<iframe>`, `<img>` หรือ `<video controls>` ได้โดยใช้ URL เดิม ส่วนปุ่มดาวน์โหลดให้เติม `?download=true` เพื่อรับ `Content-Disposition: attachment` สำหรับไฟล์ทุกชนิด SVG และไฟล์ที่ browser ไม่รองรับจะดาวน์โหลดเป็นค่าเริ่มต้น ทุก response ใช้ชื่อไฟล์เดิมแบบ UTF-8, `Cache-Control: private, no-store` และ `X-Content-Type-Options: nosniff` ตัวไฟล์ถูก stream โดยตรงจาก local storage หรือ Cloudflare R2 ผ่าน API โดยไม่คืน object key, R2 URL หรือ credentials ให้ client

### BE-15 · API หน้าแรกและสถิติ

`GET /api/home` · `GET /api/divisions/{code}/stats`

ต้องทำก่อน: BE-13

**เกณฑ์เสร็จ**

- [x] ครู: หัวข้อที่ต้องส่ง · ตัวเลขของฉัน (ส่งแล้ว / ยังไม่ส่ง / เลยกำหนด) · ส่งล่าสุด 5 รายการ · จำนวนที่ต้องส่งของแต่ละฝ่าย
- [x] หัวหน้าฝ่ายและผู้บริหาร: ตัวเลขภาพรวมทั้งโรงเรียน + แยก 4 ฝ่าย · ตัวเลขบนการ์ดฝ่าย
- [x] นับเฉพาะหัวข้อที่เปิดรับอยู่
- [x] สถิติฝ่ายดูได้เฉพาะผู้บริหารกับหัวหน้าฝ่ายนั้น คนอื่น → 403

`GET /api/home` คืน `my` สำหรับผู้ใช้ทุกคน ประกอบด้วย `counts`, `pending_topics` ที่เรียงตามกำหนดส่ง, `recent_submissions` ล่าสุดไม่เกิน 5 รายการ และ `divisions` ที่มีตัวเลขของผู้ใช้แยกทุกฝ่าย สำหรับหัวหน้าฝ่ายและผู้บริหารจะมี `overview` เพิ่มเติม ซึ่งรวมตัวเลขทั้งโรงเรียนและแยกฝ่าย ส่วนครูและแอดมินที่ไม่มีบทบาทดังกล่าวจะได้ `overview: null`

ชุดตัวเลขประกอบด้วย `topic_count`, `required_count`, `submitted_count`, `pending_count` และ `overdue_count` โดย `required_count` นับจาก snapshot ใน `topic_assignees`, `submitted_count` รวมทั้งส่งทันและส่งช้า, `pending_count` คือยังไม่ส่งและยังไม่เลยวันกำหนด และ `overdue_count` คือยังไม่ส่งหลังวันกำหนดตามเวลาไทย ทุกค่ารวมเฉพาะหัวข้อ `is_open = true`

`GET /api/divisions/{code}/stats` คืน `division` และ `stats` รูปแบบเดียวกัน ผู้บริหารเรียกได้ทุกฝ่าย หัวหน้าฝ่ายเรียกได้เฉพาะฝ่ายตน ส่วนผู้ใช้อื่นรวมถึงแอดมินที่ไม่มี content role ตอบ `403`

### BE-16 · API แฟ้มของฉัน + ดาวน์โหลด .zip

`GET /api/me/submissions?year=&q=` · `GET /api/me/files.zip?year=`

ต้องทำก่อน: BE-12, BE-14

**เกณฑ์เสร็จ**

- [x] คืนทุกอย่างที่ฉันเคยส่ง แยกตามปีการศึกษา
- [x] ค้นภาษาไทยได้ทั้งในชื่อหัวข้อ ค่าที่กรอก และชื่อไฟล์
- [x] ดาวน์โหลด .zip รายปีหรือทั้งหมดได้ โดยสตรีมออกไปทีละไฟล์ ไม่โหลดทุกไฟล์มาไว้ในหน่วยความจำ

`GET /api/me/files.zip` ไม่รับ `year` เมื่อต้องการทุกปี หรือระบุปีเพื่อดาวน์โหลดเฉพาะปีนั้น ระบบตรวจเจ้าของจาก session และ query ฐานข้อมูลก่อนเปิด object จาก local storage/Cloudflare R2 ทีละไฟล์ผ่าน stream ชื่อ entry อยู่ใต้โฟลเดอร์ `ปี/ฝ่าย/หัวข้อ/` พร้อม UUID กันชื่อซ้ำและผ่านการทำให้ปลอดภัยจาก path traversal

### BE-17 · API ค้นหา

`GET /api/search?q=&division=&year=&semester=&by=&page=&page_size=`

ต้องทำก่อน: BE-13

**เกณฑ์เสร็จ**

- [x] ค้นได้จากชื่อหัวข้อ ชื่อฝ่าย ชื่อผู้ส่ง ค่าที่กรอก และชื่อไฟล์
- [x] กรองตามฝ่าย ปี ภาคเรียน และผู้ส่งได้
- [x] คนที่ไม่มีสิทธิ์ต้องไม่เห็นคำตอบในหัวข้อลับ
- [x] แบ่งหน้าผลลัพธ์

`q` ค้นข้อความบางส่วนแบบไม่แยกตัวพิมพ์ในชื่อหัวข้อ ชื่อ/ชื่อย่อ/รหัสฝ่าย ชื่อหรือ username ผู้ส่ง JSON คำตอบ และชื่อไฟล์ `attached` รองรับภาษาไทยและ escape `%`, `_`, `\` เป็นตัวอักษรธรรมดา ตัวกรอง `division` ใช้รหัสฝ่าย, `year` ใช้ปี พ.ศ., `semester` รับ 1 หรือ 2 และ `by` รับ UUID ผู้ส่ง

response คืน `items` ซึ่งประกอบด้วยหัวข้อ ผู้ส่ง ค่าที่กรอก ไฟล์ สถานะ และวันส่ง พร้อม `pagination` ที่มี `page`, `page_size`, `total`, `total_pages`; ค่าเริ่มต้นคือหน้า 1 จำนวน 20 รายการ และขอได้สูงสุด 100 รายการต่อหน้า นอกจากนี้คืน `topics` สำหรับหัวข้อที่ชื่อตรง `q` (สูงสุด 20 รายการ) และ `topic_total` เพื่อให้หน้าเว็บแสดงส่วน “หัวข้อที่ตรงคำค้น” แยกจากคำตอบได้ ตัวกรองฝ่าย ปี ภาคเรียน และผู้ส่งมีผลกับทั้งสองส่วน และเมื่อไม่ส่ง `q` จะได้ `topics: []`

ระบบจำกัดสิทธิ์ก่อนนับและแบ่งหน้า จึงไม่เปิดเผยทั้งเนื้อหาและจำนวนคำตอบลับ ผู้ใช้ทั่วไปเห็นเฉพาะคำตอบลับของตน ส่วนผู้บริหาร หัวหน้าฝ่ายเจ้าของหัวข้อ และผู้สร้างหัวข้อเห็นทุกคำตอบตาม scope เดียวกับ BE-13 หัวข้อลับใน `topics` ใช้ขอบเขตเดียวกันและเปิดให้ผู้ที่ถูกมอบหมายค้นพบหัวข้อของตนได้แม้ยังไม่ได้ส่งคำตอบ
